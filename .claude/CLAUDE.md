# CLAUDE.md

## 1. 이해하기 쉽고 단순하게 작성 (KISS)
- 영리하거나 복잡한 코드 대신 이해하기 쉬운 코드로 작성
- 코드는 간단하고 짧게 작성

## 2. 요청받은 것만 구현 (YAGNI)
- 요청받지 않은 기능 추가 금지
- 요청받지 않은 유연성이나 설정 기능 추가 금지
- 일어날 수 없는 상황에 대한 에러 처리 금지

## 3. 추상화와 파일 구조는 최소한으로 (AHA, Flat is better than nested)
- 중복이 실제로 반복되기 전까지 추상화 금지
- 구현체가 하나뿐인 인터페이스, 베이스 클래스, 래퍼 생성 금지
- 불필요한 폴더 계층 생성 금지, 가능한 한 flat하게 유지
- 함께 바뀌는 코드는 한 파일에 유지, 불필요한 파일 분리 금지

## 4. 주석 없이 읽히는 코드 작성
- 주석 없이도 의도를 알 수 있는 코드로 작성
- 코드만으로 설명되지 않는 이유(why)가 있을 때만 주석 작성

## 5. 직접 구현 전에 검증된 라이브러리 사용 (Don't reinvent the wheel)
- 직접 구현하기 전에 표준 라이브러리, 프로젝트에 이미 있는 의존성, 외부 라이브러리 순으로 먼저 확인
- 외부 라이브러리는 검색해서 널리 쓰이고 활발히 유지보수되는 것만 사용
- 사용자가 적거나 유지보수가 중단된 라이브러리 사용 금지
- 몇 줄로 직접 작성 가능한 기능을 위한 새 의존성 추가 금지 (A little copying is better than a little dependency)

## 그림 크기 결정 (paper-figure)

수치는 `skills/paper-figure/assets/DESIGN.md` 토큰이 기준이고, 여기는 왜 그렇게 정했는지만 적는다.

- 폭: 학회와 단 수(1, 1.5, 2단)로 정한다. 사용자가 정하는 값이라 작업 전에 묻는다.
- panel 높이는 폭과 상관없이 인치로 고정한다. XS = 1, S = 1.5(기본값), M = 2, L = 2.5, XL = 3 in. SQ는 panel 폭과 같은 높이(1:1).
  - 글씨와 tick 간격이 인치로 고정이라, 높이도 고정해야 같은 단계에서 y 눈금 수가 폭과 상관없이 같다. 단계마다 0.5 in(눈금 2개)씩 늘어난다.
  - 대신 같은 단계라도 폭이 넓으면 납작해진다. 모양으로 비교하는 grid와 small multiples는 SQ를 쓴다.
  - 사용자가 aspect를 직접 정하는 기능은 두지 않는다. 데이터가 모양을 정할 때만 `finalize_figure`가 자동으로 정한다: heatmap은 칸 정사각형, y = x 대각선이 있으면 정사각형, 눈금 없는 embedding은 정사각형.
- panel 사이 간격: 사이에 들어가는 글자 공간 + panel 크기의 5%(가로는 폭, 세로는 높이 기준).
- 숫자 tick: 축을 따라 0.25 in마다 하나, 간격은 1, 2, 2.5, 5 × 10ⁿ. 숫자는 건너뛰지 않고, 겹치면 간격을 넓힌다. x축은 가장 긴 숫자가 들어갈 때까지 넓힌다.
- 데이터 여백: panel 가장자리에서 0.125 in(인치 고정, 데이터 범위 비율 아님).
- 글씨: 기본 7 pt. 숫자 tick만 5 pt, 이름 tick은 7 pt. 그림 안 글씨도 7 pt이고, 안 들어가면 5 pt로 줄인다. legend는 항상 7 pt.
- 확인: `examples/layouts/layouts.py`가 모든 배치를 `docs/layouts/`에 그린다. `skills/paper-figure/assets/`를 고치면 hook(`.claude/settings.json`)이 자동으로 다시 그린다.
